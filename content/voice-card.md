# Voice Card & Positioning Guidelines

## Positioning Pillars

1. **Prompt Engineering & Vibe Coding**: Demonstrating how clear structured prompts and low-code/vibe-coding workflows yield production-ready applications.
2. **Functional Software Execution**: Grounding every claim in working code, GitHub repos, APK builds, and live Streamlit endpoints.
3. **Human-Centric Design & Creative Writing**: Blending technical CS fundamentals with narrative design and thoughtful UI micro-interactions.

---

## Tone Guidelines

| Do | Don't |
| :--- | :--- |
| Use direct, active, concise phrasing. | Use corporate buzzwords ("synergy", "disruptive", "paradigm shift"). |
| Clearly describe what was built and decided. | Make exaggerated skill claims ("master", "expert", "revolutionary"). |
| Disclose tools used (Android Studio, Gemini, Claude). | Claim AI output as manual code without attribution. |
| Use explicit evidence placeholders `[TO ADD: ...]` when proof is needed. | Invent metrics, testimonials, or fake live links. |

---

## Authentic Voice Sample

> "I build AI applications by pairing structured prompt design with practical front-end and mobile frameworks. Rather than spending weeks writing boilerplate logic, I use vibe-coding tools to prototype rapidly, refine system prompts for accuracy, and package the logic into intuitive, working applications like BUDS and Visa Helper AI."
