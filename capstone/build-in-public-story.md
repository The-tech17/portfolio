# Build-In-Public Story: Lessons, Real Win & Real Limitation

## What I Built

Over the course of 10 weeks during my FlyRank AI Internship, I set out to build a comprehensive portfolio anchored strictly in real software execution. I created **BUDS** (a Kotlin Android multi-LLM companion app), **Visa Helper AI** (a Streamlit/Python RAG assistant), an **AI Spam Classifier**, and this modular portfolio.

---

## Why I Built It

As a Prompt Engineer and B.Tech student in Computer Science and Business Systems, I wanted to prove that prompt engineering is not just typing casual queries into a chat box—it is a rigorous software discipline combining system prompts, API orchestration, and intuitive interface design.

---

## One REAL Win

> **Engineering Zero-Shot JSON Output Reliability**: My biggest win was structuring system prompts for EcoTrace and Visa Helper that reliably force LLM models (Gemini API) to output strictly formatted JSON arrays (`{ "document": "Passport", "format": "PDF" }`) without markdown wrapping or conversational filler, achieving 100% parse success in web views.

---

## One REAL Limitation

> **Manual API Key Dependencies in Android APK**: A current limitation of the BUDS Android build is that compiling the APK outside of configured environment variables requires manual insertion of Gemini/Claude API keys into the local configuration properties, rather than utilizing a serverless proxy gateway.

---

## What I Learned

Vibe coding and prompt engineering dramatically accelerate prototyping, but foundational computer science principles—async state management, clean architecture, accessibility, and strict QA—are what turn prototypes into reliable, production-grade applications.
